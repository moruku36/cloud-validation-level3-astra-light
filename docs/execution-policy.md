## 実行
- A→B→Cの順、1回につき指定された1工程のみ。次工程へ自動移行しない。
- サブエージェントを使用しない。完了済み調査・実装・試験を理由なく繰り返さない。
- 会話は結論・判断事項・GitHubリンクを簡潔に、詳細はファイルに保存する。
- 不足情報は重要度順にまとめ、進行可能な未回答事項のみ仮定と影響を記録する。
- 判断に必要な単価・仕様のみ公式資料で確認し、出典と確認日を保存する。
- 実際の残りトークン数を取得できなければ把握を主張しない。
- 重要な判断・試験ごとに成果物と再開情報を更新する。
- 指定モデル：GPT-6 Astra Light。実際の実行モデル識別は未確認。指定名を実測値として記録しない。

## GitHub
- 初回に保存先と公開範囲を確認し、指定後は再確認しない。公開範囲を独断で変更しない。
- README.md、docs/requirements.md、docs/decisions/、experiments/A/・B/・C/、infra/、.github/workflows/、handoff.md、resource-inventory.md、evaluation/を使用。
- 全成果物、初回案、修正案、失敗、取得可能な会話・操作記録を保存する。
- 秘密情報・個人情報・機密値を含むStateやPlanは保存せず、除外理由と代替証跡を記録する。
- 工程ごとにコミット・GitHubへ反映する。設計・実装変更はPRに記録し、明示指示なしにマージしない。
- 反映失敗・未反映は明記し、次工程へ進まない。

## 再開
- 開始時はhandoff.md、resource-inventory.mdと今回の工程に必要なファイルだけを読む。
- handoff.mdに完了工程、コミット・ブランチ・PR、確定事項・仮定、未完了・阻害要因、次回1工程、コマンド・試験・期待結果、残存リソース・削除期限、費用実績・見込み・不確定部分、承認済み操作範囲を残す。

## 費用・cleanup
- A・Bはクラウドリソースを作成しない。
- C開始前に実験全体・各工程の費用上限、保持期限、操作許可範囲を確定する。
- 可能な範囲で実験ID・所有者・有効期限をタグ付けする。
- Cの開始時、各試験終了時、実行終了時に残存リソースを確認する。
- 不要リソースは証跡保存後、工程内で削除する。原則、日をまたぐ前に課金リソースを削除し、次回IaCで再構築する。
- 停止だけで無課金と判断しない。ディスク・IP・LB・NAT・DB・バックアップ・ログ等の残存費用を確認する。
- 継続保持は理由・想定費用・削除期限を記録し、事前承認範囲に限定する。
- State・復旧情報は依存リソースの削除確認前に消さない。削除対象は実験で作成・管理したリソースのみ。
- 予算アラートを課金停止機能とみなさない。無人時間の削除を約束しない。
- Cでは期限切れ削除の仕組みを検討・動作確認する。用意できない場合は終了時削除し、日をまたいで残さない。
