# LEVEL3 検証コンテキスト要約（軽量インデックス）

本ファイルは、エージェントが再開時に最小限のトークンで全体の前提仕様と現在フェーズを把握するための要約です。

## 1. アプリケーション前提仕様
- **種別**: 新規国内B2C Webシステム（会員管理・画像配信・通知）。**公開URL・実エンドポイント非公開**。
- **データ**: 個人情報保護のため**日本国内リージョン完結保管**。退会後30日削除、バックアップ35日保持。
- **負荷**: 通常 10 RPS、ピーク 100 RPS（15分間、読書比率 9:1）、同時接続 500人。
- **SLO / 可用性**: 暦月 99.9%以上。単一障害時 RTO ≤ 30分・RPO ≤ 5分。夜間専任なし（自動復旧必須）。
- **月額予算上限**: 税込 100,000 円 / 月（本番＋最小開発環境）。

## 2. アーキテクチャ構成（AWS優先参考設計）
- **コンピュート**: ECS Fargate (ARM64 / Graviton) 2タスク（2AZ分散配置）。
- **DB**: Amazon RDS for PostgreSQL (Multi-AZ、gp3)。
- **外部入口**: ALB + AWS WAF + Route 53 + ACM (HTTPS)。
- **ストレージ**: Amazon S3（画像アップロード用、暗号化・署名付きURL）。
- **非同期・通知**: Amazon SES（国内リージョン送信、DKIM/SPF設定）。

## 3. Phase C 実機検証フローとルール
- **短期実験予算枠**: 12,495 円 ＋ U（安全バッファ込 18,742 円 ＋ U）。
- **完全削除原則**: 各工程（C-1〜C-10）完了時、および日跨ぎ前に課金リソースを原則完全削除。
- **構成区分**:
  - `L` (Low / 機能用): 1タスク / 単一AZ、小型DB。機能・権限・再構築確認用。
  - `H` (High / 本番相当): 2AZ 2タスク＋Multi-AZ RDS。HA・負荷・障害復旧実証用。
- **工程一覧**:
  - `C-0`: 承認ゲート（予算・期限・操作範囲の確定）
  - `C-1`: 隔離環境構築(L) │ `C-2`: 機能/認証/SES(L) │ `C-3`: 負荷/片AZ容量(H)
  - `C-4`: 無人復旧/制御DB障害(H) │ `C-5`: 論理破損/退会再削除(H) │ `C-6`: 国内DR復元(H)
  - `C-7`: 1000 RPS(シナリオ1) │ `C-8`: 月額2倍分析(シナリオ3) │ `C-9`: Public IP禁止(シナリオ4) │ `C-10`: Cleanup・引継ぎ
